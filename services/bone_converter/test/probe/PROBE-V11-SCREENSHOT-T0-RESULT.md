# PROBE-V11-SCREENSHOT-T0-RESULT

> 阶段 1b：播放前/起始瞬间关键时机截图多模态量化分析报告（v11-t0 6 张）
> 分析方法：gts-screenshot-analyze skill → Kimi K2.7 多模态（`opencode-go/kimi-k2.7-code`），6 张并行逐张分析
> 结论性质：**视觉量化估计**（截图 1280x800，角色在视口占比约 1/4~1/3，角度为 Kimi 视觉估计，存在 ±5°~±10° 误差）；相机偏角会混入「躯干旋转」读数，需以「肘部弯曲 / 前臂错开」等相机无关特征为准

## 0. 一句话结论

**兄弟反馈的「上半身 ~60° 旋转 + lower arm 横向错开」在 `animloaded`（加载动画后未播放，re-pose 已生效、mixer 未驱动）这一时刻被完整复现**：躯干扭转 50°~60°、肘部明显弯折（上下臂夹角 120°~135°，即错开 30°~45°）、前臂相对上臂向内侧横向错开。而 **play0（播放后 ~0.1s，mixer 第 0 帧附近）已回到接近自然 Idle（躯干 5°~10°、仅肘部轻微前弯 20°~30°）**。

→ 结论：**60° 错误帧出现在「加载动画后未播放」（animloaded），是 re-pose 基准问题**，不是 mixer 起始问题。mixer 一旦开始驱动（t≈0），第 0 帧就覆盖了错误姿态。这解释了阶段 1「播放中 4 张全部正常」——错误帧只存在于 re-pose 生效到 mixer 首次驱动之间的窗口。

## 2. 关键数据点：决定性对比（animloaded vs play0）

- **animloaded**：躯干 50°~60°（向右）、双臂外展 20°~30°、**肘部夹角仅 120°~135°（前臂相对上臂向内横向错开 30°~45°）**、Kimi 明确判定「双手未自然下垂，躯干大幅扭转且手臂外展、肘部弯曲，属于轻度扭曲/非对称待机姿势」。**这就是兄弟描述的「上半身转 60° + lower arm 横向错开」的完整特征组合。**
- **play0**（与 animloaded 同一相机、仅 0.1s 之后）：躯干降到 5°~10°、肘部只剩轻微前弯 20°~30°、整体「较接近自然待机站姿，双手下垂但肘部微弯」。**mixer 第 0 帧即覆盖了 re-pose 的错误基准。**

两个时刻相隔约 0.1s、相机一致，读数差异只能用「re-pose 基准错误 → mixer 立即纠正」解释。**不是 mixer 起始问题**——若 mixer 起点就错，play0 不可能回到 5°~10°。

## 3. play1/2/3 高躯干读数的解释（相机偏角，非 pose 错误）

play1/2/3 躯干读数为 30°~50°，但伴随的**肘部/前臂错开量均很小（5°~25°，且无 animloaded 那种「前臂向内横错 + 明显肘弯」组合）**。根据 d5-animation 场景，demo 截图使用多个侧前相机（camera1 `[1.0,0.95,1.5]`、camera2 `[-1.5,0.95,1.2]`，约为正前方偏转 35°~45°），因此「躯干旋转」读数中混入相机偏角。判读准则：**以相机无关特征（肘部弯曲量、前臂错开方向/量级）为准**——play1/2/3 均无 animloaded 的异常组合，判定为自然 Idle 的正常晃动与相机视角叠加。

兄弟实机看到错误帧的时机 = **点击「加载 Mixamo 动画」后、尚未点击「播放」（或播放首帧渲染前）的窗口**。该窗口内模型展示的正是 re-pose 输出。播放后 0.1s 即恢复正常，所以阶段 1 的「播放中」截图全部正常。**矛盾彻底钉死：re-pose 基准错 ~60°。**

## 5. 结论：错误时机定位 + 给阶段 2 的决策依据

- **60° 错误帧出现时机**：`animloaded`（加载动画后未播放），即 **re-pose 后、mixer 首次驱动前**。
- **根因定性**：**re-pose 基准问题**（reposeModelBind / normalizeRootMotion 的 rest 帧基准算错，输出躯干扭转 ~60° + 前臂内错 ~30°~45° 的错误静止姿态），**不是 mixer 起始问题**。
- **给阶段 2 的 BDD 断言设计依据（重点）**：
  1. **必须新增「加载动画后未播放」状态的断言**（当前 d5-animation 场景只断言轨道匹配率 + 播放中状态，完全没覆盖 re-pose 输出的静止姿态）——这正是错误暴露的时刻。
  2. 断言内容应测「re-pose 后静止姿态」：躯干相对垂直轴扭转 ≤ 15°~20°、肘部上下臂夹角 ≥ 150°（无 120° 级弯折）、前臂相对上臂无横向错开（错开角 ≤ 15°）。期望值是「自然下垂」，绝不能是 60° 扭转。
  3. 实现层面定位点：`src/tool/bone_converter/reposeModelBind.ts` 与 `normalizeRootMotion.ts`——re-pose 基准（rest frame 提取 / 髋胸根部对正）输出错误，TDD 应针对「re-pose 后静态姿态」建立红-绿循环。
  4. 现有「播放中」断言（阶段 1 基线：扭转 ≤15°、外展 ≤20°、上下臂夹角 150°~180°）保留，作为回归保护。

## 6. 失败态排除说明

未触发「全部 6 张无 60° 级异常」的失败态：`animloaded` 明确复现 50°~60° + 肘弯 + 前臂错开，与兄弟反馈逐项吻合。无需回头找兄弟确认缓存/时机。

## 7. 备注

- 角度为 Kimi 视觉估计，存在 ±5°~±10° 误差；但「animloaded 存在 60° 级扭转 + 肘弯 120°~135° + 前臂横错」与「play0 已近自然」是明确且一致的定性结论。
- play1/2/3 高躯干读数受相机偏角影响，不作为 pose 异常证据；play0（正面/近正面视角）与 animloaded 对比成立，是根因定位的关键证据。
