`src/tool/bone_converter/normalizeRootMotion.ts` 手臂路径从 V9 帧校正改为 **D10 swing3 公式**后复用本探针：

- **Q1（相对旋转 gap，目标已从帧校正改为 swing3 retarget）**：8 骨 × 10 时间点 **全部 ≤ 0.1°** —— 输出精确复现 swing3
- **Q3（网格朝向 vs 动画）**：**mesh 方向 == 动画方向**（t=0 上臂 L 34.38°/R 29.13°，前臂 L 11.49°/R 3.25°，与 animPosFromDown 完全一致，偏差 **0°**；V9 时 mesh L 95~99°/R 74~78°、偏差 41~64°）
- **Q5（逐 t 判定）**：**全部 10 个采样点 → `正常`**（V9 时全部 → `双侧外展过度`）
- **Q1 gap 口径说明**：帧校正目标 `animQ·animBindQ⁻¹` 本身绝对朝向错（V9 外展过度根因），swing3 输出必然偏离它（旧口径 164° 属预期）；故 Q1 目标改为独立复算的 swing3（`Twist·Swing`），正确实现 gap≈0，V8 raw animQ / V9 帧校正 / joint-space 都会真实 RED

**修复公式（D10 swing3，推导见 normalizeRootMotion.ts 内 D10 注释）**：

```
worldQ(b,t) = Twist · Swing
  v(b)      = bindQ(b)⁻¹ · bindSegDir_world        # 模型 bind 局部段方向
  Swing     = 最短旋转(v → animSegDir(t))           # 方向修正（轴 ⊥ animDir，twist 贡献 0）
  roll      = twist(animQ(b,t), animSegDir(t))      # 动画真实滚动
  Twist     = 绕 animSegDir(t) 转 roll
```

- **方向**：`meshDir = worldQ·bindQ⁻¹·bindDir = Swing·v = animDir` → S16 dev=0
- **滚动**：`twist(Twist·Swing, animDir) = roll`（两旋转轴垂直，twist 可加；代数 2·atan2(cos(β/2)sin(α/2),cos(α/2)cos(β/2))=α）→ rollVsAnim=0，防掌心朝后
- **位置**：仍走 poseQ（raw animQ）→ S4/S13 位置断言不断
- 附注：S16 断言新增到 BDD（24 项全部 <20°，实测 0°）；`worldTwistAngle` 修复了 renormalize 压缩失真 bug（主导 swing 四元数角度被误测，探针实测真值 135.4° 被误测 ~53°）

## 逐问分析

### Q1：蒙皮相对旋转 gap(t) —— 全 t ≤ 0.06°，帧校正动态保持 ✅

`gap(t) = angle( worldQ_out·bindQ_model⁻¹ , animQ(t)·animBindQ⁻¹ )`（S14 的动态版）

- 8 根手臂骨 × 10 个时间点，gap **全部 ≤ 0.06°**；worst 0.06° @RightForeArm t=0.5
- 结论：**帧校正公式在任意 t 都精确复现**——输出骨骼的蒙皮相对旋转恒等于动画的相对旋转，无动态脱节，无 t 相关异常
- 这说明输出骨朝向 = `animQ·animBindQ⁻¹·bindQ` 这个**目标本身**，探针要追问的就是「这个目标是否导致视觉扭曲」

### Q2：双臂对称性（左 vs 右镜像）—— 原始数值 174~178°，但需谨慎解读 ⚠️

| 量 | 模型输出 | 动画（anim t） |
|---|---|---|
| Arm 镜像夹角 | 174.27~178.49° | 1.25~6.68°（**对称**） |
| ForeArm 镜像夹角 | 170.09~174.8° | 13.3~18.4°（近似对称） |

- 模型输出左右臂世界朝向四元数**极不对称**（~175°），而动画自身是**对称**的（Arm ~4°）
- **但**：Q2b 基线显示 **bind 本身 154.21°（Arm）/158.09°（ForeArm）、animRest 126°**——同一镜像公式对「双臂朝相反水平方向」的 T/A-pose 骨骼恒给 ~150°（因为指向 +X 与指向 -X 的旋转差 180°，x 翻转镜像公式无法把 Z 旋转的指向翻过来）。所以 **Q2 的绝对数值是 T/A-pose 固有伪信号，不能作为「单侧扭曲实锤」判据**
- 有效结论：动画双臂是对称的（Arm 4°），模型输出双臂相对动画在**世界朝向层面**被大幅改变——但这个改变是否视觉可见，取决于 Q3/Q7 的网格实际渲染
- **随 t 变化**：Q2 各值全 t 恒定（174~178°），无「某 t 突然增大」→ 无单侧扭曲实锤

### Q3：段方向 vs 竖直向下 —— 骨骼链对、网格朝向错 🔴

| 0 | 31.95 / 28.18 | 95.59 / 76.72 | 34.12 / 30.48 | **61.47 / 46.24** |
| 1.5 | 33.54 / 29.97 | 99.22 / 73.70 | 35.61 / 32.09 | **63.61 / 41.61** |
| 3 | 31.78 / 26.91 | 95.24 / 78.57 | 33.96 / 29.27 | **61.28 / 49.30** |
| 4 | 33.46 / 28.77 | 99.31 / 75.17 | 35.53 / 30.96 | **63.78 / 44.21** |
| 5.94 | 32.21 / 26.75 | 95.42 / 78.67 | 34.38 / 29.13 | **61.04 / 49.54** |

- **骨骼链位置**（poseQ walk，S4 测的）：L 32°/R 27°，与动画 34°/30° 一致 ✅ —— 这就是 BDD S4/S13 全绿的原因：**断言测的是骨骼链位置，而位置是对的**
- **网格蒙皮朝向**（= `worldQ_out·bindQ⁻¹` 施加到 bind 段方向 = 真正渲染到屏幕上的）：L 95~99°、R 74~78°（从竖直向下量）→ 手臂**外展抬起**，比动画（34°）多 **41~64°**
- 这是「断言 vs 视觉」gap 的第三形态：**骨骼链与网格解耦**——骨架位置挂在 poseQ 上（正确），蒙皮朝向挂在 worldQ（帧校正）上（错误朝向）

## 明确根因归属

### ① 不是「t 相关动态脱节」（Q1 证伪）

8 骨 × 10 时间点 gap 全 ≤ 0.06°——帧校正公式在任意 t 都精确复现 `animQ·animBindQ⁻¹·bindQ`。不存在「poseQ 调和动态脱节」这类 t 依赖 bug。

### ② 是「帧校正目标本身的绝对朝向错误」（双侧、t 不变）🔴

- 输出骨世界朝向 = `animQ(t)·animBindQ⁻¹·bindQ`（帧校正公式），gap≈0 证明代码忠实实现了它
- 但该公式只保证「相对自身 bind 的旋转与动画一致」，**不保证「绝对朝向与动画一致」**。当模型 bind（Tripo A-pose）与动画 rest（Mixamo T-pose）的世界朝向差很大（Q2b：Arm 154°、animRest 126°）时，把动画的相对旋转施加到模型 bind 骨上，得到的手臂绝对方向 ≠ 动画手臂方向
- 实测后果：模型网格手臂停在 **~70~110°（从竖直向下量）**，动画真实手臂 **~34°** → 外展过度 41~64°，双侧且 t 不变
- **为什么 BDD 39/39 全绿**：S14 断言的是 gap（帧校正内部一致性，恒≈0）；S4/S13 断言的是骨骼链位置（poseQ，正确）——两者都没测「**蒙皮网格**实际朝哪」。这正是 V8 教训的延续：**断言参考系/被测对象与「屏幕渲染」脱节**，只是这次脱节对象从「raw anim」变成了「帧校正目标」

### ③ 与 E2E 截图 Kimi 结论吻合

Kimi 判「左臂外展抬起、双臂不对称、前臂疑似轻度内旋」——探针证实：双臂**双侧**外展过度（网格 ~70~110°，非动画的 34°），左臂略重（mesh 偏差 L 61~64° > R 41~50°），配合世界朝向镜像差 175°，足以造成截图上的不对称/内旋观感。

## 结论

> **动画播放中（t≠0）手臂确实扭曲——是代码 retarget 缺陷，不是动画内容，不是截图角度。**
> 具体为「帧校正目标本身朝向错」：`worldQ=animQ·animBindQ⁻¹·bindQ` 在模型 bind 与动画 rest 世界朝向差 ~154°（Q2b）的前提下，无法把模型手臂带到动画姿态（34°），网格停在 ~70~110° 外展位，双侧且 t 不变。**需 bot 重新调度修复**。
